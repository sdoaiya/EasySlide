# EasySlide 编辑部工作桌 UI 基线：10 轮自动迭代记录

> 日期：2026-07-26  
> 状态：已收敛，规则已同步到 `docs/UI_RULES.md`  
> 关联产品计划：`docs/superpowers/plans/2026-07-26-content-project-workspaces-implementation-plan.md`

## 总体结论

“编辑部工作桌”适合作为 EasySlide 的长期视觉方向。它与桌面生产力工具定位、作品优先的信息层级、克制动效和现有 UI 规则一致，但原始版本仍以 PPT 为唯一作品对象，并且没有解决固定导航与三栏编辑器的宽度冲突。

经过 10 轮自动迭代，最终定义为：

> EasySlide 是一间有灵感、但秩序井然的数字工作室。作品承担视觉表现，工具保持冷静；创意通过真实封面、纸张材质和少量索引色表达，不依赖营销 Hero、渐变、炫光或装饰堆叠。

## 第 1 轮：作品对象

**原方向：** 首页采用四列 PPT 封面墙。

**冲突：** 统一内容项目允许首次创建视频或播客，这些项目可能没有 PPT 封面。继续使用 PPT 作为首页唯一视觉对象，会把视频和播客重新降级为附属功能。

**收敛：** 首页改为四列“内容项目作品墙”。封面按最近使用的已初始化工作区选择：

1. PPT：首张有效页面；
2. 视频：用户封面或代表场景关键帧；
3. 播客：节目封面；
4. 均无可用封面：使用确定性的模式占位，不调用 AI 临时生成。

卡片显示项目标题、更新时间、聚合状态，并用紧凑图标/标签表达已初始化的工作区，不把项目重新标记为单一类型。

## 第 2 轮：70/20/10 的含义

**原方向：** 作品舞台 70%、灵感墙 20%、创作流程 10%。

**冲突：** 若实现为固定高度百分比，会在 1280x720 中挤压作品，在项目数量变化时制造大片空白。

**收敛：** 70/20/10 是信息权重和开发投入比例，不是 CSS 高度。首屏顺序固定为：紧凑品牌/创建条、作品墙主体、露出下一段灵感墙标题或首行。作品墙拥有页面主要面积；创作流程不成为 Hero。

## 第 3 轮：单一静止工具架

**原方向：** 左侧 `216px` 固定导航始终静止。

**冲突：** 当前编辑器已有 `216px` 页面栏与 `320px` 属性栏。若再叠加一条全局 `216px` 导航，1280px 下中央画布会被压缩到不可用。

**收敛：** 任一视口最多只有一条 `216px` 左侧工具架：

- 首页、创建、设置：显示应用级导航。
- 进入项目：同一外壳切换为返回项目中心、Content Spine/PPT/视频/播客和当前页面/场景/片段索引。
- 禁止在项目工作区内部再叠第二条完整侧栏。
- 左栏 DOM 外壳保持挂载，不参与页面切换动画；内容切换不改变宽度。

## 第 4 轮：四列网格与稳定尺寸

**原方向：** 首页四列封面陈列。

**冲突：** 需要证明固定导航后在最小验证视口仍能容纳四列，不产生标题和操作溢出。

**收敛：** 在 `>=1280px` 使用 `repeat(4, minmax(0, 1fr))`，主区水平内边距 24px，列间距 16px。封面槽固定 `aspect-ratio: 16 / 9`，状态和悬停工具绝不能改变卡片尺寸。低于 1280px 才允许降为三列或两列，不通过压缩字体维持四列。

## 第 5 轮：操作显隐与可访问性

**原方向：** 编辑、导出、删除只在悬停或选中后出现。

**冲突：** 仅悬停对键盘和触控不可用；完全隐藏也会让关键操作不可发现。

**收敛：** 操作在 `hover`、`focus-within`、选中和批量模式下出现；触控环境常驻一个“更多”图标入口。删除仍需确认，导出进入任务中心。操作层使用绝对定位覆盖预留区域，不改变卡片高度。所有图标按钮具有 `aria-label`、tooltip 和至少 40px 点击区域。

## 第 6 轮：色彩与按钮

**原方向：** 冷白/雾灰、墨黑文字，墨黑主按钮，红黄绿小细节。

**冲突：** 现有规则和 token 将系统蓝同时用于主按钮、选择、链接和焦点。直接把 `--app-accent` 改黑会损害焦点识别和迁移可控性。

**收敛：** 拆分语义：

- `primary-action`：墨黑/近白反色，用于每屏唯一主命令；
- `focus`：系统蓝，只用于焦点、链接和需要强识别的选择状态；
- `index-red/yellow/green`：标签、页码、章节索引和状态细节；
- 错误/警告/成功继续使用语义红/黄/绿，并配文字或图标，禁止只靠颜色。

普通按钮不使用红黄绿铺底。危险按钮只在确认场景使用错误色。

## 第 7 轮：适度拟物边界

**原方向：** 细纸纹、纸张错层、半透明胶片和彩色标签。

**冲突：** 若每个面板都使用材质和错层，会与禁止卡片套卡片、桌面工具信息密度及深色模式冲突。

**收敛：** 材质只属于作品封面、模板预览和空状态作品占位；工具栏、表单、设置和属性栏保持近实色。纸张最多一层 `2-3px` 错位边缘，不使用随机角度；胶片只用于媒体类型/选中覆盖；纹理使用低对比位图，禁止 CSS 渐变伪造纸纹。

## 第 8 轮：Anime.js 动效职责

**原方向：** 页面切换和封面悬停都接入 Anime.js。

**冲突：** 简单 hover 用 Anime.js 会增加生命周期和清理成本，且可能与键盘/快速指针切换竞争。

**收敛：**

- Anime.js 仅负责右侧工作区路由内容的 `160-200ms` 淡入与最多 `4px` 的轻微状态位移。
- 左侧工具架不重新挂载、不位移、不参与 stagger。
- 封面 hover 使用 CSS `transform: translateY(-2px)` 至 `-4px` 与阴影过渡。
- 只动画 `transform` 和 `opacity`；切换时保持输入可用并清理旧 animation。
- `prefers-reduced-motion` 下取消位移，使用不超过 100ms 的淡化或即时切换。

## 第 9 轮：跨页面迁移

**原方向：** 同一组件语言迁移到创建、项目、素材和设置。

**冲突：** 若机械复制首页纸张风格，会导致工具页面卡片化；“素材中心”也可能被误解为已完成的统一多媒体素材库。

**收敛：**

- 创建页：使用模式优先的紧凑流程，真实预览可以有纸张材质，表单本身不拟物。
- 项目工作区：作品/画布是视觉主角，左右工具表面保持安静。
- 素材入口：首发明确为“图片素材”；视频/播客音频素材留在各自工作区。
- 设置页：保持高密度分组、分隔线和表单，不使用封面墙语言。
- 任务中心：保持操作性和可追踪性，不增加编辑部装饰。

## 第 10 轮：验收与停止条件

**原方向：** 在三个桌面视口完成视觉检查。

**冲突：** 仅看静态截图无法发现悬停依赖、导航重挂载、动效未清理和长标题溢出。

**收敛：** 发布前必须同时验证：

- `1280x720`、`1440x900`、`1920x1080`，Windows 100%/125%；
- 鼠标、键盘、触控/无 hover、reduced motion；
- 四列网格、最长标题、空封面、视频/播客封面、批量选择和操作显隐；
- 路由切换期间左栏像素稳定、右侧无重叠、动画可中断；
- 首页第一视口以作品为主，并露出灵感墙线索；
- CSS/TSX 扫描无大面积渐变、装饰光晕、随机旋转、嵌套卡片和直接业务色值。

若四列作品墙导致 1280px 下卡片信息或操作无法容纳，应缩短元信息或改为覆盖操作，不能缩小字体或叠加横向滚动。若单一 `216px` 工具架无法承载项目模式与内容索引，先做分组/折叠，不增加第二条完整侧栏。

## 最终设计基线

### 首页

- `10%`：紧凑品牌/快速创建条；不是 Hero。
- `70%`：四列内容项目作品墙；真实封面承担视觉表现。
- `20%`：少量精选模板和图片素材灵感墙；位于作品之后。
- 项目操作只在 hover、focus-within、选中或触控“更多”中出现。

### 视觉

- 冷白/浅雾灰画布、白色表面、墨黑文字和墨黑主操作。
- 系统蓝保留给焦点、链接和强选择状态。
- 红黄绿只做有语义的索引、状态和细节，不铺满普通按钮。
- 适度纸纹、单层错位边缘和胶片覆盖只用于作品类视觉对象。

### 导航

- 全应用只有一条 `216px` 静止工具架。
- 项目内将应用导航、工作区导航和当前内容索引收敛到同一左栏层级。
- 中央内容与右侧属性栏按现有 WorkspaceShell 约束布局，不因左栏内容变化改变宽度。

### 动效

- Anime.js：右侧页面/工作区的短路由过渡。
- CSS：封面 hover、按钮 pressed 和普通控件状态。
- 左栏静止；无大幅飞入、弹跳、长 stagger 或持续循环。

### 范围

本基线改变 UI 视觉和信息架构，不改变 Content Spine、工作区、版本、同步、迁移、任务和导出协议。统一内容项目实施时以本文件的收敛结论和 `docs/UI_RULES.md` 为 UI 验收依据。

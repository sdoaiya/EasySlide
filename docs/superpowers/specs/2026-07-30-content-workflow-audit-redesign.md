# 三模式内容项目流程审计与重设计

## 审计结论

当前系统已经有统一项目、Content Spine、PPT/video/podcast workspace、版本和导出任务，但用户路径仍然是“创建后立刻跳进工作区”。创建 API 返回 `202` 后，初始化任务在后台运行，目标 workspace 在此期间仍显示 `uninitialized`，因此用户会看到可以重复点击的初始化入口；失败也没有明确的重试语义。

另外三个模式的出口不对称：PPT 直接进入既有编辑器，视频有 Proof -> Final 门禁，播客只有文本编辑与 MP3/WAV 导出。视频/播客共用版本和任务底座，但没有共用一套可见的“准备 -> 编辑 -> 校验 -> 导出”阶段模型。

本轮已先修复初始化状态根因：队列时写入 `stage=QUEUED`，执行时写入 `INITIALIZING`，成功写入 `DRAFT`，失败写入 `FAILED`；入口页轮询准备状态，准备中隐藏重复按钮，失败显示重试。创建响应里的 `task_id` 现在登记到现有任务 store，刷新后可在任务中心继续轮询。

## 统一用户模型

所有模式都遵循同一条主线：

```text
输入资料 -> 内容主线(Spine) -> 工作区准备 -> 编辑成稿 -> 预检/Proof -> Final 导出 -> 产物与版本
```

用户只选择三件事：

1. 输出模式：PPT、视频、播客。
2. 内容来源：一句话、提纲、完整稿件、文件导入。
3. 是否从已有工作区派生：例如从 PPT 生成视频。

其余设置在对应工作区内完成，不在创建页堆叠模式专属参数。

## 三模式流程

### PPT

`输入 -> Spine 草稿 -> 确认主线 -> 页面结构 -> 视觉生成/原生编辑 -> PPT/PDF/图片导出`。

创建页只保留渲染模式、画幅和模板入口；页面生成、图片质量、翻新和导出都在 PPT 工作区内。空白 PPT 也先创建 Spine 和空 workspace，避免一条入口绕开项目模型。

### 视频

`输入或 PPT 派生 -> Spine 确认 -> 场景准备 -> 场景/旁白/字幕/音频编辑 -> Proof -> 人工检查 -> Final`。

Proof 是必经的可见阶段。Final 只能引用同一 workspace revision 的已完成 Proof；任何保存、同步或场景修改都会使旧 Proof 失效。音频素材在工作区内选择并执行授权/文件存在预检。

### 播客

`输入 -> Spine 确认 -> 片段与说话人准备 -> 脚本/声音/片段试听 -> 混音预检 -> MP3/WAV + 逐字稿 + 封面清单`。

单人和多人只改变节目文档，不改变导出任务模型。试听、BGM/SFX、ducking、封面和逐字稿属于同一工作区；删除或替换被引用素材必须先预检，不能生成半成品。

## 统一状态机

工作区使用 `state` 表示可编辑性，使用 `stage` 表示当前流程阶段：

```text
uninitialized/QUEUED
  -> uninitialized/INITIALIZING
  -> draft/DRAFT
  -> draft/PREFLIGHT
  -> draft/PROOF (视频)
  -> ready/FINAL (导出完成)
```

任意阶段可进入 `FAILED`，入口显示失败原因和重试；重试重新读取冻结 Spine 或最新 workspace revision，不复用不完整产物。同步冲突、素材缺失、Proof 过期都属于阻断原因，而不是静默降级。

## 实施顺序

1. **已完成：** 初始化阶段标记、入口页轮询、重复提交保护和失败重试。
2. **下一步：** API 在项目摘要中返回 workspace stage/task summary；首页和工作区任务中心显示同一条状态。
3. **然后：** 将视频 Proof 失效规则和播客混音预检统一接入 WorkspaceStatusBar；所有导出按钮只从预检结果启用。
4. **最后：** 将创建页收敛为“模式 + 内容来源 + 输入”，把 PPT 专属设置迁移到 PPT 工作区；补三模式创建到真实产物的 E2E。

## 验收门禁

- 创建任一模式后，初始化期间不能重复提交，刷新页面仍能看到准备中状态。
- 初始化失败后可以重试，且不会产生半个 workspace version。
- 视频修改后旧 Proof 不可用于 Final；Final 必须带同版本 Proof 引用。
- 播客单人/多人均可试听、预检并导出 MP3/WAV、逐字稿和封面清单。
- 三模式都能从同一个项目壳层切换，任务暂停/恢复和质量报告入口一致。
- 1280x720、1440x900、1920x1080、125% 缩放、键盘和 reduced-motion 门禁全部通过。

## 暂不做

不在本轮引入新的媒体库、第二套任务引擎或多成品 Artifact 层；真实 Fish Audio 凭据、人工听检、数据库副本迁移和桌面生产包仍是发布前外部门禁。
